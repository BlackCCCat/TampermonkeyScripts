Subject
JavaScript 广告过滤正则的结构、零宽断言与扩展方法

先看骨架：它其实是一组布尔条件

把关键词暂时折叠掉，原表达式就是下面这个逻辑。它不是“从左到右找一段广告文本”，而是先在字符串开头连续做几项真假检查，检查通过后再匹配整段文字。

/^
(?!.*(?:排除词))
(?:
    (?=.*(?:强广告词))
  | (?=.*(?:平台词))(?=.*(?:促销词))
  | (?=.*(?:联系方式))(?=.*(?:商业意图))
)
[\s\S]+
$/i

逐段理解

1. / ... /i：表达式边界和标志

前后两个斜杠是 JavaScript 正则字面量的边界；最后的 i 表示英文大小写不敏感。因此 VX、vx、Vx 都可以命中。这里不需要 g，因为脚本只需要判断一条动态“是否匹配”，不是提取所有出现位置。

2. ^ 和 $：把检查固定到整条动态

^ 表示输入开头，$ 表示输入结尾。由于所有前瞻都从开头执行，里面的 .* 就能搜索整条动态，而不会从中途换一个位置重新尝试。

3. (?!.*(?:排除词))：负向前瞻

(?!X) 的意思是：“从当前位置往后不能匹配 X”。这里的 X 是 .*(?:不是广告|非广告|反诈提醒...)，所以只要全文任何地方出现排除词，整条规则就立即失败。

零宽的关键：它只回答“条件成立吗”，不会把任何字符算进最终匹配结果。检查完成后，正则仍停在字符串开头。

4. 外层 (?: A | B | C )：三个命中方案任选其一

(?:...) 是非捕获分组，只负责组织结构，不保存子匹配结果；| 表示“或者”。所以 A、B、C 三个广告判定分支只要有一个成立即可。

5. 分支 A：一个强广告词就足够

(?=.*(?:广告|推广|赞助|商务合作|带货|领券|优惠券|...))

这是一个正向前瞻：(?=X) 要求 X 必须能匹配。它用 .* 扫描全文，只要找到任一强广告词就通过。这个分支灵敏，但也是最容易误伤的地方，例如“吐槽广告太多”也含有“广告”。

6. 分支 B：平台词和促销词必须同时出现

(?=.*(?:美团|淘宝|天猫|京东|拼多多|...))
(?=.*(?:红包|优惠|补贴|满减|领券|下单|...))

相邻的两个前瞻相当于逻辑 AND。第一个要求全文存在平台名，第二个要求全文存在促销意图。它们不要求两个词紧挨着，也不关心先后顺序：

  • “淘宝今天有满减”会命中。
  • “满减活动请去淘宝看”也会命中。
  • “我今天用美团点了晚饭”只有平台词，没有促销词，不命中。

7. 分支 C：联系方式和商业意图必须同时出现

(?=.*(?:私信|加微(?:信)?|V信|VX))
(?=.*(?:咨询|购买|合作|报价))

这也是 AND 条件，用来识别“私信购买”“加微信合作”一类引流。内部的 微(?:信)? 表示先匹配“微”，后面的“信”可有可无，因此能覆盖“加微”和“加微信”。

8. [\s\S]+：前面检查，最后这里才真正消费字符

[\s\S] 表示“空白字符或非空白字符”，合起来就是任意字符；+ 要求至少一个。前面的零宽断言全部通过后，这一段负责匹配整条动态，直到 $。

用样例建立直觉

动态文本结果原因
淘宝今晚满减，点击链接下单屏蔽平台词 + 促销词，分支 B
我今天用美团点了晚饭放行只有平台词，没有促销词
商务合作请私信报价屏蔽“商务合作”触发 A；联系方式 + 商业意图也触发 C
这不是广告，是反诈提醒放行先被负向前瞻排除
最近看到的广告太多了屏蔽含强广告词“广告”；这是可能的误伤

以后怎么添加

  1. 新增明确广告词：加到分支 A，例如 |恰饭|商单。
  2. 新增平台名：加到分支 B 的平台组，例如 |唯品会|得物。只有同时出现促销词才会命中。
  3. 新增促销动作：加到分支 B 的第二组，例如 |砍价|秒杀|包邮。
  4. 修复误伤：优先把明确语境加到最前面的排除组，例如 |广告行业分析。
  5. 新增一种组合逻辑：在外层增加一个 | 分支，用多个前瞻表达 AND。
/^(?!.*(?:排除词))(?:(?=.*(?:强广告词))|(?=.*(?:平台词))(?=.*(?:促销词))|(?=.*(?:联系方式))(?=.*(?:商业意图))|(?=.*(?:新条件一))(?=.*(?:新条件二)))[\s\S]+$/i

维护原则：单个词即可断定广告的，放分支 A；容易误伤、必须结合上下文的词，拆成两个前瞻放进组合分支。平台名通常不应该单独放进分支 A。

如果新增内容包含正则特殊字符 . * + ? ^ $ { } ( ) | [ ] \ /，想匹配它本身时要在前面加反斜杠。由于整条规则以斜杠作为边界，正文里的字面量斜杠应写成 \/。
