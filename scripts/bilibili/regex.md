正则的核心不是“找一个关键词”，而是在表达下面这个布尔逻辑：

```text
不包含排除词
AND
(
  包含强广告词
  OR
  (包含平台词 AND 包含促销词)
  OR
  (包含联系方式 AND 包含商业意图)
)
```

原始结构可以格式化成：

```regex
/
^
(?!.*(?:排除词))
(?:
    (?=.*(?:强广告词))
  | (?=.*(?:平台词))(?=.*(?:促销词))
  | (?=.*(?:联系方式))(?=.*(?:商业意图))
)
[\s\S]+
$
/i
```

## 1. `/.../i`

```regex
/正则主体/i
```

前后的 `/` 是 JavaScript 正则表达式边界。

末尾的 `i` 表示英文大小写不敏感：

```text
VX
vx
Vx
```

都会视为相同内容。中文不受大小写影响。

这里不需要 `g`，因为脚本只是判断每条动态“是否命中”，不是提取所有匹配位置。

## 2. `^` 与 `$`

```regex
^ ... $
```

- `^`：从整条动态的开头开始。
- `$`：必须检查到整条动态结尾。

它们把整个正则固定为“检查一整条动态”。

## 3. 负向零宽断言

```regex
(?!.*(?:不是广告|非广告|拒绝广告|广告屏蔽|广告过滤|反诈提醒))
```

拆开看：

```regex
(?! X )
```

表示当前位置后面不能匹配 `X`。

里面的：

```regex
.*
```

表示向后扫描任意内容。

因此整体含义是：

> 从动态开头向后检查，全文不能出现这些排除词。

例如：

```text
这不是广告，是一条反诈提醒
```

因为包含“不是广告”或“反诈提醒”，所以直接放行。

这就是“零宽”的含义：它只检查条件是否成立，不会消耗任何字符；检查结束后，匹配位置仍停留在字符串开头。[MDN 对前瞻断言的说明](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Regular_expressions/Lookahead_assertion)

注意：排除词优先级非常高。只要出现一个排除词，后面的广告条件全部失效，所以不要把太宽泛的词放进去。

## 4. 非捕获分组与 OR

```regex
(?: A | B | C )
```

其中：

- `(?:...)`：非捕获分组，只负责组织结构。
- `|`：逻辑 OR，也就是“或者”。

这表示 A、B、C 三个方案只要满足一个就屏蔽。

普通的 `(...)` 会保存匹配结果；这里不需要读取分组内容，所以使用 `(?:...)` 更合适。[MDN 分组说明](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Regular_expressions/Groups_and_backreferences)

## 5. 分支 A：强广告词

```regex
(?=.*(?:广告|推广|赞助|商务合作|品牌合作|带货|领券|优惠券|返利))
```

`(?=X)` 是正向零宽断言，意思是后面必须能匹配 `X`。

因此这段表示：

> 全文只要出现任意一个强广告词，就视为广告。

适合加入：

```regex
恰饭|商单|返佣|品牌赞助|付费推广
```

修改后类似：

```regex
(?:广告|推广|赞助|商务合作|恰饭|商单|返佣)
```

这个分支最容易误伤。例如：

```text
最近看到的广告太多了
```

也包含“广告”，所以仍会被屏蔽。

## 6. 分支 B：平台词 AND 促销词

```regex
(?=.*(?:美团|淘宝|天猫|京东|拼多多|饿了么))
(?=.*(?:红包|优惠|补贴|满减|领券|下单|购买))
```

两个正向前瞻连续出现，相当于逻辑 AND：

```text
存在平台词
AND
存在促销词
```

所以：

```text
淘宝今晚有满减活动
```

会命中。

而：

```text
我今天用美团点了晚饭
```

只有“美团”，没有“红包、优惠、满减”等促销词，因此不会命中。

两个词不要求相邻，也不要求固定顺序：

```text
淘宝今天有满减
满减活动可以去淘宝看看
```

两者都能命中。

增加平台时，放进第一个分组：

```regex
美团|淘宝|天猫|京东|拼多多|饿了么|唯品会|得物
```

增加促销动作时，放进第二个分组：

```regex
红包|优惠|补贴|满减|领券|下单|购买|秒杀|砍价|包邮
```

## 7. 分支 C：联系方式 AND 商业意图

```regex
(?=.*(?:私信|加微(?:信)?|V信|VX))
(?=.*(?:咨询|购买|合作|报价))
```

它要求同时存在：

```text
联系方式
AND
商业意图
```

例如：

```text
需要购买请加微信咨询
商务合作私信报价
```

都会命中。

其中：

```regex
微(?:信)?
```

表示：

- 必须有“微”；
- 后面的“信”可有可无，因为 `?` 表示出现零次或一次。

所以它可以匹配：

```text
加微
加微信
```

## 8. `[\s\S]+`

```regex
[\s\S]+
```

- `\s`：空白字符。
- `\S`：非空白字符。
- `[\s\S]`：两者合起来就是任意字符。
- `+`：至少出现一次。

前面的零宽断言只做检查，真正把整条动态内容匹配掉的是这一段。

在当前脚本里，动态文本已经被归一化成单行，因此通常使用 `.+` 也可以；`[\s\S]+` 对包含换行的原始文本更加稳妥。

## 添加规则的位置

可以遵循这个判断：

| 想添加的内容 | 添加位置 |
|---|---|
| 单独出现就能确定是广告 | 强广告词分支 |
| 美团、淘宝等平台名称 | 平台词分支 |
| 满减、红包、下单等动作 | 促销词分支 |
| 加微信、私信等方式 | 联系方式分支 |
| 购买、报价、合作等目的 | 商业意图分支 |
| 明确不应屏蔽的语境 | 最前面的排除词 |

如果想增加一种新的组合条件，可以新建 OR 分支：

```regex
|(?=.*(?:直播平台词))(?=.*(?:促销动作))
```

完整模板：

```regex
/^(?!.*(?:排除词))(?:(?=.*(?:强广告词))|(?=.*(?:平台词))(?=.*(?:促销词))|(?=.*(?:联系方式))(?=.*(?:商业意图))|(?=.*(?:新条件一))(?=.*(?:新条件二)))[\s\S]+$/i
```

最重要的维护原则是：

> 单个词足以判断广告的，放在分支 A；容易误伤、必须结合上下文的，拆成多个正向前瞻表达 AND。
